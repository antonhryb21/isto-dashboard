# ISTO · Marketing dashboard

Реклама Meta, пости Instagram і Facebook та міні-CRM лідів ISTO в одному місці.

- **Огляд** — витрати, ліди без спаму, ціна ліда і якісного ліда, зустрічі, угоди, порівняння з попереднім періодом.
- **Реклама** — кампанії з результатами в CRM (скільки лідів стали якісними і дійшли до угоди).
- **Креативи** — кожне оголошення з візуалом і ціною якісного ліда.
- **Соцмережі** — пости IG і FB з охопленням, збереженнями, репостами; позначка, які пости бустились.
- **Воронка** — від показу реклами до угоди.
- **CRM** — головна база лідів: список і дошка, статус, відповідальний, сума угоди, коментарі з історією. Нові ліди приходять напряму з Meta; статуси змінюються тут або кнопками Telegram-бота.
- **Адмін** — люди з доступом і ролями, регіони, імпорт історії лідів з CSV, ручний запуск синхронізації.

Стек: Next.js 16, Postgres (Neon) + Drizzle, Vercel.

## Як оновлюються дані

| Що | Коли |
| --- | --- |
| Нові ліди з форм Meta | Миттєво, через вебхук `/api/webhooks/meta`; щодня додатково звіряються з формами за 3 дні |
| Статуси з Telegram-бота | Миттєво, через `/api/leads/status` |
| Реклама (3 дні), ліди з таблиць, свіжі пости IG | Коли хтось відкриває дашборд і даним більше 10 хв (у фоні), або кнопкою «Оновити зараз» |
| Кампанії, креативи, 30 днів реклами, пости IG і FB зі статистикою | Щодня о 03:00 UTC (Vercel Cron) |
| Історія за 12 місяців | Один раз вручну: Адмін → «Завантажити історію» |

Працює і на плані Hobby (там дозволено лише щоденний cron), але для робочого використання Vercel вимагає Pro.

## Розгортання на Vercel

1. Імпортуйте репозиторій у Vercel.
2. Storage → Neon Postgres → підключіть до проєкту (`DATABASE_URL` додасться сама). Міграції бази виконуються автоматично під час кожної збірки.
3. Додайте змінні оточення (Settings → Environment Variables):

| Змінна | Опис |
| --- | --- |
| `DATABASE_URL` | Додає Neon |
| `APP_URL` | `https://dash.ваш-домен` |
| `ADMIN_EMAILS` | Email-и, які при першому вході стають адмінами (через кому) |
| `AUTH_SECRET` | Випадковий рядок ≥ 32 символи |
| `CRON_SECRET` | Випадковий рядок; Vercel передає його в щоденний cron |
| `META_APP_ID`, `META_APP_SECRET` | Застосунок Meta «ISTO Dashboard» |
| `META_SYSTEM_USER_TOKEN` | Безстроковий токен системного користувача |
| `META_WEBHOOK_VERIFY_TOKEN` | Випадковий рядок для перевірки вебхука |
| `LEADS_API_TOKEN` | Випадковий рядок; ним Telegram-бот (n8n) підписує запити з новими лідами і статусами |
| `TELEGRAM_LEADS_BOT_TOKEN` | Токен бота, що публікує картки лідів (n8n); потрібен, щоб статуси з CRM оновлювали картки в Telegram |
| `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` | OAuth-клієнт для входу; redirect URI `https://<домен>/api/auth/callback/google` |

Необов'язкові: `GOOGLE_SERVICE_ACCOUNT_JSON_BASE64` — лише якщо треба живу двосторонню синхронізацію з Google Таблицями (за замовчуванням вимкнена); `META_API_VERSION` (за замовчуванням `v27.0`), `META_AD_ACCOUNT_IDS`, `META_PAGE_ID`, `META_IG_USER_ID` — якщо зміняться кабінети чи сторінка.

4. Redeploy → увійдіть через Google акаунтом з `ADMIN_EMAILS`.
5. Адмін → «Повне оновлення», потім «Завантажити історію за 12 міс.».
6. У Meta: App → Webhooks → Page → поле `leadgen`, Callback URL `https://<домен>/api/webhooks/meta`, Verify token = `META_WEBHOOK_VERIFY_TOKEN`. Потім Адмін → «Підписати сторінку на ліди».

## Ліди

**Нові ліди** приходять з Meta напряму. Перший запуск: Адмін → «Завантажити історію» забирає ліди з форм за останні 90 днів (більше Meta не віддає).

**Історія з Google Таблиць** — один раз: у таблиці відкрийте вкладку з лідами → Файл → Завантажити → CSV, і в Адмін → «Імпорт історії лідів» оберіть файли (можна кілька). Колонки розпізнаються за назвами (`id`, `created_time`, `campaign_name`, `phone`, `email`, `lead_status`, `New Bizz`/`owner`, `Comments`…), решта — відповіді з форми. Лід, що є в кількох вкладках, обʼєднується; статус з файлу застосовується лише до лідів зі статусом New, яких ще не змінювали в CRM чи ботом, тож повторний імпорт нічого не зіпсує.

**Статуси** — New → Contacted → Lead (Qualified) → Follow-up → Meeting → Proposal sent → Won / Lost, плюс No answer, Not relevant, Job inquiry, Supplier, Spam. Старі значення (CREATED, Новый, Spam / Supplier) зводяться до них автоматично.

### Telegram-бот (n8n)

Після натискання кнопки статусу додайте в n8n вузол **HTTP Request**:

- Method `POST`, URL `https://<домен>/api/leads/status`
- Header `Authorization: Bearer <LEADS_API_TOKEN>`
- Body (JSON):

```json
{ "lead_id": "{{ id ліда Meta }}", "status": "Contacted", "changed_by": "@telegram_нік", "comment": "необовʼязково", "owner": "необовʼязково" }
```

`status` приймає назву статусу (`Follow-up`), код (`follow_up`) або старі назви з таблиць. Невідомий статус → відповідь 400 зі списком дозволених. Якщо бот надіслав статус раніше, ніж лід потрапив у дашборд, лід буде підтягнуто з Meta автоматично.

Щоб дашборд оновлював картку в Telegram, коли статус змінили з кнопки, додайте в тіло `chat_id` і `message_id` картки, на якій натиснули: дашборд оновить решту карток цього ліда (група / особистий чат).

**Новий лід з бота.** Одразу після відправки картки n8n викликає `POST /api/leads/ingest` (той самий `Authorization: Bearer <LEADS_API_TOKEN>`):

```json
{
  "lead_id": "1977622026500180",
  "lead": { "full_name": "…", "phone": "…", "email": "…", "city": "…", "form_id": "…", "form_name": "…", "created_time": "…", "answers": {} },
  "telegram": { "chat_id": "-5398273801", "message_id": 178, "text": "<html картки>", "reply_markup": { "inline_keyboard": [] } }
}
```

Лід підтягується з Meta з повною атрибуцією реклами; якщо Meta недоступна — зберігаються дані з `lead`. Повторний виклик нічого не дублює. `telegram` запамʼятовує картку: коли статус змінюють у CRM, дашборд дописує в усі картки ліда блок «📋 Статус / 👤 Обновил / 🕒 Обновлено» у форматі бота. Для цього потрібен токен того ж бота у змінній `TELEGRAM_LEADS_BOT_TOKEN`.

### Жива синхронізація з Google Таблицями (необовʼязково)

Якщо задати `GOOGLE_SERVICE_ACCOUNT_JSON_BASE64`, дашборд читатиме ліди з таблиць Dubai/EU і записуватиме туди статуси з CRM; в Адмін зʼявиться розділ «Таблиці з лідами».

## Локальна розробка

```bash
npm install
cp .env.example .env.local   # заповніть
npm run db:migrate
npm run dev
```

Після зміни `src/db/schema.ts`: `npm run db:generate` і закомітьте нову міграцію з `drizzle/`.
